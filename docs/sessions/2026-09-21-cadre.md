# Corridor cadre — four agents, one night

*Written for: Rich, and for each agent he spawns. Each agent reads "Common rules" and its own
section only. Main (the session that wrote this) integrates, runs the bakes, merges branches and
owns the checklist. The editor agent already running in its own tree keeps the editor-knobs lane
(section 4) — nothing to spawn for it.*

## How to spawn one (Rich)

```bash
cd /workspaces/apex-conduit
git worktree add .claude/worktrees/<agent> -b agent/<agent> main   # /workspaces is root-owned; .claude/ is gitignored and is the pattern coast-editor and fighter used
cd .claude/worktrees/<agent> && npm install            # worktrees share packages/engine — without this @apex/engine resolves to the main checkout
rm -rf tools/corridor/data && ln -s /workspaces/apex-conduit/tools/corridor/data tools/corridor/data   # the baked sites live once
mkdir -p /tmp/corridor-mail/<agent>/{inbox,outbox}
```

Then start a Claude Code session in `.claude/worktrees/<agent>` with:

> You are the **<agent>** agent of the corridor cadre. Read `docs/sessions/2026-09-21-cadre.md`:
> the "Common rules" section and your own section, nothing else. Then start.

Agents: `world-look` (port 5201), `road-and-car` (5202), `terrain-and-data` (5203), `asset-library` (5204).

## Common rules (every agent)

- **Your worktree, your branch, your dev server** (`npx vite --port <port> apps/corridor`). Never
  edit `/workspaces/apex-conduit` directly. Never restart another server, the devproxy on :5190, or
  cloudflared.
- **Repro first, root cause, fix by design, re-run the repro.** Rich's rule after four rounds of
  guess-and-patch on a bug that turned out to be a horizon mesh. Every visual or behaviour claim
  you make has a headless probe under `probes/` that shows it (Playwright + swiftshader; copy the
  boilerplate from `probes/corridor-grassperf.mjs`, including the `page.route` line that blocks
  `/@vite/client` so a Vite reload cannot empty `window.corridor` mid-probe).
- **Measure, don't type.** Numbers come from data or a probe, not from a screenshot. Every
  tunable is an `export let` in `apps/corridor/src/tuning.ts` with a `tune()` entry; Rich drives,
  pastes the panel's JSON, you set the default.
- **Ownership is by file** (your section). Shared files — `scene.ts`, `main.ts`, `tuning.ts`,
  `index.html`, `style.css`, `editor/main.ts`, `catalog.json`, `export.py` — are additive-only: add
  a section, a knob, a case, a manifest key; never restructure, never revert a line you did not
  write. Bigger than that: mail main first.
- **Mail.** Numbered markdown files with `subject:` on line one into
  `/tmp/corridor-mail/<you>/outbox/`; main answers into your `inbox/`. Mail when you start, when
  you need a decision or a shared-file change, and at handoff (what shipped, the probe that proves
  it, knobs added, what is left).
- **Green before handoff:** `npx tsc -b apps/corridor` and `npx oxlint apps/corridor`. Commit on
  your branch, clear messages; main merges. Do not push; do not touch `main`.
- **Conventions that bit people today:** three.js `rotation.y = θ` sends local +Z to
  `(sin θ, 0, cos θ)`; a placement `yaw_deg` is a compass bearing rendered `-(yaw·π/180)`; the
  bake's `rect.yaw_deg` is a math angle from east (`yaw = -rect.yaw_deg`); tsconfig has
  `erasableSyntaxOnly` (no constructor parameter properties); custom ShaderMaterials need the
  `common` + `logdepthbuf_*` chunks or they vanish; ShaderMaterial fog is fixed at compile time.
- **Traps that cost a lane hours each (2026-09-21/22).**
  * `requestAnimationFrame` **does not fire in a background tab**, and background `setTimeout` is
    clamped to ~1 Hz. Anything budgeted that yields on a frame stops dead when the tab loses focus
    — page responsive, nothing spinning, progress frozen. Two rounds were lost to this before
    anyone checked `document.visibilityState`.
  * The dev-bridge context is **`window.__apex`**, not `window.corridor`. Both exist and both
    carry `site`/`scene`/`camera`/`THREE`, so probing the wrong one *works* while silently lacking
    `renderer` and `perf`.
  * **swiftshader cannot measure frame time** (flat 16 ms to ~576k triangles, then 3-4 s/frame),
    and neither can a hidden tab. Ask main to run it on the real GPU; do not quote a percentile
    you did not measure.
  * `RasterFrame.toGrid` **clamps** and returns normalised 0..1 — it cannot answer "is this point
    inside". Use `contains()`.
  * **Never `git add -A` in `/workspaces/apex-conduit`.** It is a shared tree and lanes edit in it
    uncommitted; two lanes swept up other people's mid-edit files in one day. Stage explicit paths.
- **A probe must assert the MECHANISM and fail loudly if it did not run — and you must prove the
  assertion can fail before you trust it.** One lane's tally: two real code bugs against five
  instruments that said "fine" without checking (a switch count that scored a backwards fade as a
  90% win; a reseed check that passed when the command had not run; a log piped through `tail -6`
  that discarded the numbers; `/mph/` matching "0 mph" so a stationary car passed "the car moves";
  an action that silently did nothing). The recurring failure in this codebase is **rendered
  perfectly while being wrong**.
- **Coordinates:** scene x = site x, scene z = −site y. `groundAt(x, y)` takes site y;
  `Site.heightAt` / `Site.edgeDistance` take scene x, z (edgeDistance < 0 = on pavement).
  **Since 2026-09-22 "site metres" are TRUE ENU about `manifest.frame.anchor`, not UTM minus an
  origin.** `frame.kind` (`"enu"` / `"utm"`) is the only thing that says which, and guessing wrong
  rotates the world by the grid convergence — 55 m at 3 km, and it looks plausible. A raster is
  still on its own projected grid and carries a lattice (`layers.<x>.geo`); place and sample it
  with `RasterFrame` from `@apex/engine/geo/raster`, never with bbox arithmetic. Bearings are true
  bearings now. See `docs/corridor/FRAME.md`.
- **Where things are:** baked data `tools/corridor/data/sites/<slug>/` (`site.json`,
  `spine_utm.json`, `osm.geojson`, `dem_1m.tif`, `lidar/{dtm,dsm,chm,deck_*}.tif`, `profile.json`,
  `web/manifest.json` + layers). Texture generation `tools/surfaces/gen.py` (flux.2 on gh200-1,
  `FLUX_VERIFY=0`). 3D props: flux → TRELLIS.2 via `tools/recon-service` (URL in its README),
  Draco GLBs into `apps/corridor/public/assets/` + `catalog.json`. Session checklist:
  `docs/sessions/2026-09-21-corridor.md`; **where everything actually stands, and who owns what is
  outstanding: `docs/sessions/2026-09-22-fleet.md`** — read that before picking up any task below,
  several of which have shipped or changed owner since this brief was written.

6. **`docs/corridor/ASSETS.md`**: the pipeline, the spec format, the scores and what they mean,
