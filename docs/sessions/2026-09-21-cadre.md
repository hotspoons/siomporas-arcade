# Corridor cadre — three agents, one night

*Written for: Rich, and for each agent he spawns. Each agent reads "Common rules" and its own
section only. Main (the session that wrote this) integrates, runs the bakes, merges branches and
owns the checklist. The editor agent already running in its own tree keeps the editor-knobs lane
(section 4) — nothing to spawn for it.*

## How to spawn one (Rich)

```bash
cd /workspaces/apex-conduit
git worktree add ../apex-<agent> -b agent/<agent> main
cd ../apex-<agent> && npm install                      # worktrees share packages/engine — without this @apex/engine resolves to the main checkout
rm -rf tools/corridor/data && ln -s /workspaces/apex-conduit/tools/corridor/data tools/corridor/data   # the baked sites live once
mkdir -p /tmp/corridor-mail/<agent>/{inbox,outbox}
```

Then start a Claude Code session in `../apex-<agent>` with:

> You are the **<agent>** agent of the corridor cadre. Read `docs/sessions/2026-09-21-cadre.md`:
> the "Common rules" section and your own section, nothing else. Then start.

Agents: `world-look` (port 5201), `road-and-car` (5202), `terrain-and-data` (5203).

## Common rules (every agent)

- **Your worktree, your branch, your dev server** (`npx vite --port <port> apps/corridor`). Never
  edit `/workspaces/apex-conduit` directly. Never restart another server, the devproxy on :5190, or
  cloudflared.
- **Repro first, root cause, fix by design, re-run the repro.** Rich's rule after four rounds of
  guess-and-patch on a bug that turned out to be a horizon mesh. Every visual or behaviour claim
  you make has a headless probe under `probes/` that shows it (Playwright + swiftshader; copy the
  boilerplate from `probes/corridor-grassperf.mjs`, including the `page.route` line that blocks
  `/@vite/client` so a Vite reload cannot empty `window.corridor` mid-probe).
- **Measure, don't type.** Numbers come from data or a probe, not from a screenshot. Every
  tunable is an `export let` in `apps/corridor/src/tuning.ts` with a `tune()` entry; Rich drives,
  pastes the panel's JSON, you set the default.
- **Ownership is by file** (your section). Shared files — `scene.ts`, `main.ts`, `tuning.ts`,
  `index.html`, `style.css`, `editor/main.ts`, `catalog.json`, `export.py` — are additive-only: add
  a section, a knob, a case, a manifest key; never restructure, never revert a line you did not
  write. Bigger than that: mail main first.
- **Mail.** Numbered markdown files with `subject:` on line one into
  `/tmp/corridor-mail/<you>/outbox/`; main answers into your `inbox/`. Mail when you start, when
  you need a decision or a shared-file change, and at handoff (what shipped, the probe that proves
  it, knobs added, what is left).
- **Green before handoff:** `npx tsc -b apps/corridor` and `npx oxlint apps/corridor`. Commit on
  your branch, clear messages; main merges. Do not push; do not touch `main`.
- **Conventions that bit people today:** three.js `rotation.y = θ` sends local +Z to
  `(sin θ, 0, cos θ)`; a placement `yaw_deg` is a compass bearing rendered `-(yaw·π/180)`; the
  bake's `rect.yaw_deg` is a math angle from east (`yaw = -rect.yaw_deg`); tsconfig has
  `erasableSyntaxOnly` (no constructor parameter properties); custom ShaderMaterials need the
  `common` + `logdepthbuf_*` chunks or they vanish; ShaderMaterial fog is fixed at compile time.
- **Coordinates:** scene x = site x, scene z = −site y. `groundAt(x, y)` takes site y;
  `Site.heightAt` / `Site.edgeDistance` take scene x, z (edgeDistance < 0 = on pavement).
- **Where things are:** baked data `tools/corridor/data/sites/<slug>/` (`site.json`,
  `spine_utm.json`, `osm.geojson`, `dem_1m.tif`, `lidar/{dtm,dsm,chm,deck_*}.tif`, `profile.json`,
  `web/manifest.json` + layers). Texture generation `tools/surfaces/gen.py` (flux.2 on gh200-1,
  `FLUX_VERIFY=0`). 3D props: flux → TRELLIS.2 via `tools/recon-service` (URL in its README),
  Draco GLBs into `apps/corridor/public/assets/` + `catalog.json`. Session checklist:
  `docs/sessions/2026-09-21-corridor.md`.

## 1 · world-look — port 5201

**Goal.** Everything that touches the ground and the air, under one owner because it is one
rendering problem: a contextual base ground, grass that stays ahead of the car and reads like
September, seasons in the tuner, a real winter, and weather.

**Owns:** `src/grass.ts`, `src/strip.ts`, `src/hextile.ts`, `src/season.ts`, `src/trees.ts`
(season parts), new `src/{groundcover,weather,sky}.ts`, `tools/surfaces/gen.py` (ground classes),
new `tools/corridor/corridor/cover.py` + a `cover_2m.png` layer in `export.py` (additive), the
`grass` / `ground` / `season` / `weather` tabs in `tuning.ts`, `probes/corridor-grassperf.mjs`.

**Tasks, in order.**
1. **Grass acceptance probe.** `probes/corridor-grassperf.mjs` dies before measuring (HMR reload or
   a `waitForFunction` that never resolves). Make it work: drive a Bowie stance (Rich's is in
   `/tmp/claude-1000/-workspaces-apex-conduit/397fba92-5e84-41c5-9605-5d43678842ec/scratchpad/rich_grass_stance_url.txt`)
   8 s at speed; print median/p90/p99/max frame time, spikes > 60 ms, `site.grass.counts`
   (blades, cards, tiles, pending). Main rewrote `grass.ts` tonight into cached 8 m tiles
   (blades near, sprite cards far, wind off above 4 m/s, colour/sprite knobs) — unmeasured.
2. **Grass keeps up.** At 30 m/s the ring must never show bare tiles ahead: watch `pending`; if it
   grows, move tile generation to a Web Worker (sample ground/canopy/road-distance to a small
   per-tile raster first — generation is then pure) or cut per-tile cost. Cards out to 1–1.5 km at
   low density with no pop (size fade exists; try a second coarser card tier at one per 4 m²).
   Tuft atlas baked from the real blade shader (4–6 cells: mown/rough/wheat/bermuda × summer/
   autumn; `impostors.ts` shows the atlas pattern) so near blades and far cards match.
3. **Regional grass.** `grass_type` per site (default from latitude/longitude + `manifest.landuse`:
   farmland → `wheat`) and per adjustment area: `common`, `wheat` (tall, straw), `bermuda` (low,
   tight — SoCal), `coastal` (sparse dune grass, long lean). September palettes per season with
   `GRASS_DRY_ADD` folded in; Rich says everything looks like April.
4. **The float.** Repro on a Bowie fly stance along the verge: hide strip / terrain / imagery until
   the metre-or-two gap between landscape and imagery shows which surface is which (likely the
   2 m DEM terrain vs the strip's lidar heights). One-sentence cause, then fix.
5. **Cover classes in the bake** (`cover.py`): per 2 m cell → `turf | forest_floor | rock | sand |
   soil | crop | water | paved` from CHM (canopy > 3 m → forest floor), slope + geology
   (`manifest.geology`) + lidar intensity (rock), OSM landuse (farmland → crop; beach), NAIP colour,
   OSM water. 8-bit class PNG on the DEM lattice + legend in the manifest. Test trio: Bowie
   (suburban), Sideling (rock cut), Clarksburg (interstate).
6. **Cover textures + shader.** `gen.py` prompts per class: colour + normal + height, 3 variants,
   same hex tiling as pavement. A ground shader that samples the class layer and blends 2–3 sets
   with a 1–2 m dither band; displacement as vertex offset on the strip, normal-only on the far
   terrain; season tint. The strip's mown/rough textures become `turf`; grass stands on it.
7. **Season in the F6 panel.** The engine `TunePanel` takes numbers: a 0–3 knob mapped to the four
   seasons is fine (or an enum control added additively to `packages/engine/src/app/TunePanel.ts` —
   shared with other games; mail main).
8. **Winter.** Leaves off (sparse/bare leaf sets exist in `trees.ts::setSeason`), leaf litter as a
   `forest_floor` weight, dead-straw grass, impostor atlas rebaked (`impostors.rebake`).
9. **Weather.** Rain / sleet / snow / ice: instanced particles in a camera-following box driven by
   the grass gust field; wet-road look (roughness/albedo on pavement); fog and sky tint per weather;
   accumulation 0–1 as a white blend on upward normals through one shader chunk that strip,
   terrain and pavement all include; ice as glaze. Expose `WEATHER_GRIP_SCALE`; `car.ts` (road-and-
   car's file) reads it — mail them the name.

**Done when:** the grass probe shows p99 < 40 ms with no spikes at 30 m/s on Bowie and cards at
1 km without pop; wheat/bermuda selectable and visibly different; forest floor under trees and
turf on the verge with no seam at the pavement; Sideling's cut reads as rock; four seasons and
four weathers switch live from F6 (screenshots on Braddock); snow visibly builds; frame time
within 3 ms of tonight's.

**Owns:** `src/props.ts` (roadMesh, surface sets), new `src/paint.ts` if you split paint out,

`camera` tabs in `tuning.ts`, `probes/corridor-handling.mjs`.

**Tasks, in order.**

9. **A car.** A TRELLIS or free GLB (catalog pattern in `placements.ts`), steering and spinning
   wheels; the red box goes.

**Done when:** handling probe numbers before/after in the handoff; launches only over real crests

## 3 · terrain-and-data — port 5203

**Goal.** The Python side and the documents: detect cuts and canyons and dress them with rock,
detect exposed rock and falls (Bonnie Branch Road is baking tonight), represent water, write the
pipeline/design docs Rich asked for, and report coverage for the 16 new sites as they land.

**Owns:** new `tools/corridor/corridor/{cuts,rock,water}.py`, manifest keys `cuts`, `rock`,
`water` (additive in `export.py`), new `src/rocks.ts`, `src/water.ts`, rock GLBs via the recon
service (`category: "rock"` in `catalog.json`, append only), `docs/corridor/**` (new),
`tools/corridor/{README,DESIGN}.md`, `apps/corridor/README.md`.

**Tasks, in order.**
1. **`docs/corridor/PIPELINE.md`** — read the code, do not guess. Prebaked (`tools/corridor`): sites
   (photo EXIF or lat/lon) → OSM spine/features/crossings/buildings → 3DEP DEM → NAIP → lidar
   (EPT, TNM LAZ fallback) → DTM/DSM/CHM/deck rasters → profile + structures (class-17 demotion,
   deck planarity) → surface classes → geology → 60 km horizon → `web/` layers + `manifest.json` →
   publish (R2). Realtime (`apps/corridor`): terrain from DEM, corridor strip, road + paint from
   spine/lanes, hex-tiled flux surfaces, ez-tree near trees + impostor atlas from CHM, grass tiles,
   detected + authored structures, catalog placements, adjustments, minimap, car. Where every
   texture and model comes from (flux.2 on gh200-1; flux → TRELLIS.2 recon service; ez-tree presets
   and its bundled bark/leaf textures; USGS/OSM/Macrostrat) and **where TRELLIS props slot in**
   (`catalog.json` entries with `category`/`fit`/`yaw_offset_deg`; `structures.json` bridge assets;
   autogen categories; your rock kit).
2. **`docs/corridor/DESIGN.md`** — frames, the one-height-function rule (carriageway spline), the
   LOD footprint, the grass tile design, detection rules, the sign conventions above. A one-page
   "how to add a road" (photo or lat/lon → `sites.json` → `just corridor-fetch` → viewer).
3. **`docs/corridor/SITES.md`** — as bakes land (log:
   `/tmp/claude-1000/-workspaces-apex-conduit/397fba92-5e84-41c5-9605-5d43678842ec/scratchpad/newbakes.log`):
   per site the lidar project/year/classes, NAIP date, OSM lane tags, what is missing, and any
   failure with its error. The 16: Patuxent River, Bacon Ridge, Chesterfield, Crownsville, Underwood,
   Waterbury, Rutland, Rossback, Hawkins, Bell Branch, St Stephens Church, Bonnie Branch, Ragged
   Point, Bixby, Ecola, Acadia.
4. **Cuts** (`cuts.py`): from `profile.ground_rel` (ground at 8/15/25/40/60 m beside the surface)
   and the DTM — a cut face is ground rising > 0.6 m/m within 15 m of pavement for ≥ 20 m; classify
   `artificial` (straight, constant slope, parallel) vs `natural` (ravine walls both sides,
   following a stream). Sideling and Braddock have the big ones; Bonnie Branch the natural ones.
5. **Rock** (`rock.py`): exposed rock = bare ground with high 1 m roughness, no canopy, slope > 30°,
   + geology lithology (shale/siltstone/schist/granite) + NAIP grey/brown → polygons with a rock
   type. **Kit:** 4–6 boulder/ledge GLBs per lithology via flux → TRELLIS, placed along cut faces
   with the tree instancing pattern (`props.ts::treesFromCanopy`), never on pavement
   (`edgeDistance`).
6. **Water** (`water.py`, `water.ts`): OSM `waterway=*` / `natural=water` (already in
   `osm.geojson`; NHD if easy) → a water mesh at the DTM low line with an animated normal shader;
   falls/rapids where a stream drops > 2 m over 20 m → whitewater card strip. Bonnie Branch is the
   test.
7. Probes: a Sideling fly stance with dressed cut faces; a Bonnie Branch fly-through with water.

**Done when:** the three docs exist and match the code; the sites table is filled for every
finished bake; Sideling's cut faces carry rock; Bonnie Branch shows its stream and a falls; water
renders on every site that has it.
