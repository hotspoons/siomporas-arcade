## The one thing that changed everything

**Corridor's world is no longer flat.** It was UTM metres minus a per-site origin — a plane, with
no curvature, a scale factor, and a north that is not north. It is now **true ENU metres about a
declared geodetic anchor**, on the WGS84 ellipsoid. All 21 baked sites are converted and live.

Design, measurements and the order of work: **`docs/corridor/FRAME.md`**. The short version of
why, measured at Crofton's own anchor:

| effect | size | verdict |
|---|---|---|
| grid convergence (UTM north vs true north) | **1.0594°** | a rotation, not an error |
| scale factor | ~135 ppm | small |
| residual horizontal after removing both | < 0.34 m at 25 km | UTM was fine horizontally |
| **curvature a plane cannot represent** | **0.70 m @ 3 km · 49.0 m @ 25 km** | the real problem |

So the win is the vertical and the ability to stitch sites, not horizontal accuracy. The 1.06°
rotation is invisible inside one site and fatal between two — and it is what produced every frame
bug below.

**`manifest.frame.kind` is the only thing that says which metres a manifest holds** — `"enu"` or
`"utm"`. Guessing wrong rotates the world and it looks plausible.

Verified: 21/21 sites round-trip to their UTM originals within 25 mm (`scripts/verify_enu.py`),
and on Rich's GPU the terrain falls away from the tangent plane by 3.97 m at 7,112 m where the
ellipsoid says 3.96 m.

## What each lane shipped

### orchestrator (main, :5185, dev bridge on Rich's GPU) — live

- **The geodesy core**: `packages/engine/src/geo/wgs84.ts` (Anchor, ECEF, ENU, floating-origin
  rebase, global quadtree matching trailworks) and `geo/raster.ts` (RasterFrame: place a raster on
  the ellipsoid and invert it). Checked against **pyproj/PROJ**, not against itself, and
  cross-checked against the bake's own Python `Anchor` across four UTM zones.
- **The bake emits ENU**: vectors converted exactly; rasters keep their native grid and carry a
  geodetic control lattice (`layers.<x>.geo`, 9×9 per raster, 3×3 per tile — 18 mm over a whole
  site, measured).
- **Staged bakes and atomic promotion**: `corridor export --staged` / `promote` / `rollback`,
  swapping with `renameat2(RENAME_EXCHANGE)` — one syscall, no instant without a `web/`, and the
  old tree survives so rollback is the same operation. `promote` refuses a staged tree missing
  files the live one has.
- **Tile packs** in trailworks' format, **KTX2 twins** beside every baked jpg.
- Three performance fixes before any of that: an O(427) strip lookup (**19.1 s → 9.9 s** build),
  the canopy blanket built-then-hidden (72 MB), and gzip on the manifest.

### road-and-car / tiles (:5202) — merged `2dbbc25`

Tiled terrain streaming for a network, and it works: **crofton-crownsville streams at 19 resident
tiles = 12.1 MB of texture**, against 667 MB if all 125 were resident. Measured pair, jpg vs ktx2,
same 19 tiles: **12.1 MiB vs 87.7 MiB**.

Per-tile `RasterFrame` rather than one mosaic — the tile lattice is the UTM grid, so a mosaic
placed from `tiles.origin` is out by up to **384.9 m** across crownsville. Pack reader, coarse ENU
index, `heightAt`/`canopyAt` with the 8 m overview as fallback, `ImageryStream` with
**`budgetBytes`** eviction (their first cut capped tile *count*, which silently means 128 MB with
the jpg and 16 MB with the twin).

Heights are decoded up front, not streamed: the strip, trees, grass and car all ask on the first
frame and a missing height is a hole, not a coarser LOD.

### ui-and-assets (:5211) — `agent/ui` merged `bab751b`; `agent/assetsvc` **blocked on Rich**

Both corridor UIs rebuilt on one design system: `apps/corridor/src/ui/` (tokens, shell, controls,
generated Heroicons, IBM Plex). `style.css` deleted, both HTML files reduced to a canvas.

**Three things another lane can trip over:**
- Layer toggles are no longer `input[data-layer]`. They live in `LAYER_GROUPS` (`ui/viewer.ts`)
  and `EDITOR_LAYERS` (`ui/editor.ts`), read via `ui.layers()`. Add a layer there or it will not
  exist.
- `src/editor/ui.ts` is an adapter over the shared controls, deliberately, so `areas.ts`,
  `place.ts`, `grow.ts` and `structures.ts` did not change.
- The F6 panel is corridor-local (`ui/tune.ts`) over the same `TUNE_TABS` and the **same
  localStorage keys**. `@apex/engine/app/TunePanel` is untouched — conduit, stuntin and coast are
  unaffected.

The Site panel now reports `frame.kind`, the anchor and the convergence instead of a bare EPSG,
derived live per site.

`agent/assetsvc` (`03dcd50`, contains `agent/ui`) is the asset pipeline as a backend service —
`tools/assetsvc`, model adapters, job queue, catalog on a volume, SigV4 S3, Helm chart off by
default. Proven end to end against gh200-1: image 9.4 s via flux.2-dev, mesh 33.8 s via TRELLIS.2,
finish 623 kB from 22.7 MB. **Not deployed and not merged — see Outstanding.**

Every one of these **rendered perfectly while being wrong**. That is the shape to watch for.

| the **authored** files (`adjustments/placements/structures.json`) live outside `web/` and the re-export never touched them | editor-knobs | median 40 m, **max 439 m** | fixed + stamped `a2af7a4` |

The orchestrator's conversion handled everything the bake *writes* and never asked what sits beside
it. **A migration's blind spot is the data it does not own.**

## Traps that cost real time — read this before debugging

1. **`requestAnimationFrame` does not fire in a background tab.** The frame budget yielded on it,
   so a build stopped dead the moment the tab lost focus and never resumed — page responsive,
   nothing spinning, progress frozen on whatever it last printed. Two rounds were spent blaming
   the geodetic work before anyone checked `document.visibilityState`. Racing a timer is not
   enough either: background `setTimeout` is clamped to ~1 Hz. Fixed `8aabc03` — a hidden tab has
   no frames to protect, so it does not yield at all there.
2. **The dev-bridge context is `window.__apex`, not `window.corridor`.** Both exist and both carry
   `site`/`scene`/`camera`/`THREE`, so probing `window.corridor` *works* while silently lacking
   `renderer` and `perf`.
3. **`RasterFrame.toGrid` clamps and returns normalised 0..1.** It cannot answer "is this point
   inside" — every point comes back looking inside. Use `contains(x, z, slackM)` (`05d23fe`).
4. **`/workspaces/apex-conduit` is a shared working tree.** `git add -A` there sweeps up other
   lanes' mid-edit files; two lanes did it independently in one day. Stage explicit paths.
5. **swiftshader cannot measure frame time** (flat 16 ms to ~576k triangles, then 3–4 s/frame),
   and **neither can a hidden tab** — measured 0 frames in 4,873 ms.

And the line worth putting in the cadre doc, from editor-knobs: **a probe must assert the
mechanism and fail loudly if it did not run — and prove the assertion can fail before trusting
it.** Their day counted two real code bugs against five instruments that said "fine" without
checking.
